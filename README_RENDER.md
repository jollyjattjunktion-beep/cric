# Preet Sports Current-Ball Web Commentary — Render Patch

This is a **copy-over patch**, not a complete project archive. Copy these root files into your existing repository and keep its existing `src/` and `web/` directories (including `src/human_commentator.py`, `web/index.html`, `web/app.js`, and `web/style.css`).

## Behaviour changes

- The dashboard still gets the CREX score state and ball feed.
- Audio speech starts with the latest current delivery only, not the old match history.
- At most one waiting ball is retained. A newer delivery replaces a waiting stale one.
- Audio speaks the CREX `commentary` field, not the AI helper's rewritten `spoken_text`.
- TTS is streamed in memory to the browser using a data URI; no commentary MP3 archive is written.
- When CREX's newest ball crosses into the next over, a deterministic over recap is queued once from the source delivery badges; summaries are not generated by a free-form AI prompt.
- If a new ball arrives while older audio is being synthesized/played, outdated not-yet-broadcast audio is dropped.

## Critical security note

Do **not** upload `.env`. Set secrets in Render's Environment settings instead. A TTS key was included in the uploaded `.env` file; revoke/rotate that key before using it again. The archive excludes `.env`.

## Render installation (Docker)

1. In GitHub, open your own repository and replace `server.py` with this package's `server.py`. The `cricket_streamer.py`, `Dockerfile`, `requirements.txt`, `Procfile`, `.env.example`, `.gitignore`, `.dockerignore`, and `render.yaml` are included as convenience copies based on the uploaded files. Preserve your current `src/` and `web/` directories; do not delete those files.
2. Commit and push the changes to your deployed branch.
3. In Render, open the service connected to this repository. Under **Settings**, set Runtime to **Docker** (or leave Docker selected if the service already uses the included Dockerfile). Set Dockerfile path to `./Dockerfile`, Docker context to `.`, and Health Check Path to `/api/status`.
4. Open **Environment**. Set `PORT=10000` and `PYTHONUNBUFFERED=1`. If you choose Sarvam in the UI, add a newly rotated `SARVAM_API_KEY` secret; Edge TTS does not need that key.
5. Use **Manual Deploy → Deploy latest commit** if auto-deploy is off. Check the logs for `Cricket AI Web UI running on http://0.0.0.0:10000` and no import errors.
6. Open your `https://<service>.onrender.com/` page, choose a live match and language, then click **Start Live Broadcast**. Click/interact with the page once to allow browser audio autoplay.

## Health check

`GET /api/status` should return HTTP 200. The server binds to `0.0.0.0` and Render's `$PORT` (defaults to 10000).

## Local validation

```bash
python -m py_compile server.py cricket_streamer.py src/human_commentator.py
python server.py
```

This patch does not include `src/human_commentator.py` or the `web/` files because they were not among the uploaded files; keep the versions already present in your repository. Actual browser audio should be tested after deploying against a live CREX page.
